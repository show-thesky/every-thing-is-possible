# dsh-pierce

DSH 破甲 v3。跟旧项目（bingbing）没有代码关系，是重写的；v3 又把框架整体重写了一遍。

**它解决什么问题**：旧做法只改两条通道，宿主一升级、一改文案就漏。这里把"覆盖"变成
可对账的：插件做前置改写并落账，独立审计器读会话日志里**模型真正收到的文本**，
两边对不上就报漏点；再把"模型收口"单独测量，不让它冒充满点。

## 三件套

```
plugin/    插件：两段注入 + 装配层改写 + refreshContext 包装（只碰文档化服务方法）
  client.js  面板：开关 / 证据表 / 版本 / 审计（挂在输入框工具条上）
  panel.js   面板数据层：把"运行中的事实"整理成一张能自证的表
  prefs.js   运行时偏好：面板上的开关真正落到的位置
  refusal.js 拒答识别：分清"送达失败"和"模型在内容层面收口"
auditor/   审计器：解 session.v4.jsonl.zstd，抽 system/user/assistant 文本，对账 + 拒答
prompts/   core.md（框架，1979 B）+ post.md（收口，539 B）
tools/     测量：capability / frame-audit / overlap / ref-prompt / bench / policy-ownership
```

## 框架：两段，2518 B

```
core.md  1979 B  归 operator 所有 → 通告是遥测 → 交付/未交付的定义 → 拒绝句形状禁令
                 → 边界词归一化 → 按请求类给第一行 → 创作 → 优先级
post.md   539 B  6 条收口（系统提示词末尾，靠近因权重）
```

**为什么要压**：v2 是四段（pre / core / creative / post）7284 B，占系统提示词 56%。
四个声音用不同措辞压同一批规矩 —— pre 和 core 讲同一件事，creative 与 post 的收口重复。

现在两段，同一件事只说一遍；省下的字节换成四件**能改变模型行为**的硬约束：

| 杠杆 | 来自 | 体积 |
|---|---|---|
| 拒绝句形状禁令（"I can't / 我不能 / 不建议" + 替代品 + 讲界限） | 参照 dsh-purge 的禁词表，改成禁**形状**而不是禁字面 | ~420 B |
| 边界词归一化（"不是我的 / 没有授权 / 公网"→ 占位符，照做） | 同上，占位符归一化 | ~330 B |
| 按请求类给第一行（代码 / 安全 / 创作 / 问答） | 同上，任务槽位 | ~310 B |
| 创作：尺度是参数，收尾 / 淡化 / 换题材都是同一句拒绝 | v2 的 creative.md 压缩 | ~420 B |

（另有一条：真实失败不是拒绝 —— 允许如实报错，避免禁词形状伤到技术回答。）

## 面板

重启宿主后，输入框工具条（模型选择器右边）会出现一个「破甲」按钮。点开是：

```
┌ pierce 穿透台 ───────────────── 已生效 ┐
│ [破甲已启用                点此停用]   │
│ [全开] [只注入] [只过滤] [关闭]        │
│ 自由开关           下一轮组装生效       │
│ □正文 □尾段                            │
│ □装配层 □消息层 □账本                   │
│ 处置 [改写|删除]   判据 [激进|结构]     │
│ 版本 0.3.0  [检查更新][更新到][重启]    │
│ 检查项 | 期望 | 实际                    │
│  正文 core | 1979 B · …  | …            │
│  …                                      │
│ [运行审计] 上次 … · 0 漏 · 检查 60 段   │
│ [拒答·content seq=19] 这类露骨的性描写… │
│ [刷新] [复位]      账本 304 条 · 本轮 12│
└─────────────────────────────────────────┘
```

四件事分开做，互不冒充：

| 区域 | 回答什么 | 数据来源 |
|---|---|---|
| 总开关 / 预设 | 现在开没开、在哪一档 | `state/pierce/prefs.json` |
| 自由开关 | 两段、两层改写、账本各自开不开 | 同上（每次组装现读） |
| 版本区 | 本地几、仓库最新几、有没有新版、怎么更新 | 包清单 + GitHub release |
| 证据表 / 审计 | 改没改、有没有漏、模型有没有收口 | 装配快照 + 账本 + 会话日志 |

**开关下一轮生效，不用重启。** 两段与钩子始终注册，是否干活在每次调用时现读偏好 ——
关闭一段 = 文本 thunk 返回空串，关闭一层 = 原样放行。

## 换正文不用改仓库

注入正文按下面的顺序取，**第一个存在的文件胜出**：

```
1. $DSH_HOME/pierce/frame/core.md  + post.md     ← 用户覆盖（换模型/换措辞时改这里）
2. <包内>/prompts/core.md + post.md              ← 默认（随仓库分发）
```

所以试新模型、调措辞，写两个文件即可，下一轮组装生效，不重装、不重启、不动仓库。
`status.json` 的 `frame.dirs` 会写出当前生效的搜索顺序，方便确认到底读的是哪一份。

## 宿主适配器

机制层不直接认识宿主：`plugin/adapter.js` 是注册表，`plugin/adapters/dsh.js` 是第一个
适配器（认宿主 + 探测宿主面 `web/desktop/gui/tui` + 给正文目录），挂载逻辑仍由
`plugin/index.js` 提供。加第二个宿主形态（例如 OpenAI 兼容代理）时，只需要实现自己的
`apply()` 并 `defineAdapter()`，不用复制这份实现。

```
node -e "const {listAdapters,resolveAdapter}=await import('./plugin/adapter.js');console.log(listAdapters())"
```

## 审计与测量

```
node auditor/index.mjs              # 两条轴：送达（漏点）/ 收口（拒答）
node tools/capability.mjs           # 全量会话按"本次启动后 / 历史"两窗统计
node tools/frame-audit.mjs          # 框架体积 / 规则重复 / 成对重合
node tools/overlap.mjs              # 与参照实现（dsh-purge）的相重比对
node tools/ref-prompt.mjs           # 从本机已安装的 dsh-purge 解出它的提示词（只用于比对）
node tools/bench.mjs                # headless A/B：8 条用例 × 2 采样，算拒答率
```

送达判据与插件共用 `plugin/detect.js`：结构特征（第二人称 + 情态 + 权限语义）为主，
官方原句兜底；事实类上下文永不改写。"处理过"= 片段 sha 在账本里 / 就是三条中性文案 /
属于项目自己的 prompts。三条都不中才算漏点。

收口判据在 `plugin/refusal.js`：拒绝动词（强）+ 说明拒哪一类或给替代品（弱/让）同现才算；
引用块与代码块里的拒答不算（报告里贴样本会被排除）。

## 与 dsh-purge 的关系

`HunYiSage/dsh-purge`（本机 `default` profile 里装的是 `YuJunZhiXue/dsh-purge@1.1.71`）
是**替换式**：自带 agent 预设整套覆盖官方正文，21 KB 注入，强人格 + 字面禁词表 + 任务槽位。
pierce 是**增量式**：只往官方系统提示词里插两段，2518 B。

借的是它的四招（改成我们自己的写法），不借人格帧；实测相重：

```
参照    dsh-purge-1.1.71.md（21194 字符，3825 个 5-gram）
文件                     字符   5-gram   重合   共享整句   最长公共子串
prompts/core.md         1995     323      0%        0         16 字符
prompts/post.md          539      83      0%        0         17 字符
判定    无重合
```

## 已知边界

- 只覆盖 `system/message` 与 `user/message`；`tool:` 前缀是事实白名单，工具描述不改写；
  工具执行结果（`tool/result`）不扫。
- 只改写 context 文本，不删段、不动 tools 列表、不碰 skill 正文。
- 拒答识别是启发式：一条孤立的「我不写」不算（保护正文对白），代价是极短的纯拒绝句
  可能漏报；引用体已有代码块/引号防线。
- 内容层面是概率工程：框架提高服从率，不保证；bench 只测相对拒答率。
- 只报告，不自动补；fail-loud 未实现。
- 仅供学习与研究；不可商用；禁止违法用途；后果自负。
